# PulseFeed 设计说明（中文）

[README](README.md) | [English DESIGN.md](../../DESIGN.md)

本文是「**为什么这么设计**」，包括那些先做错、后来改对的地方 —— 因为错误的版本通常正是读者会自己重新发明的那个。

---

## 1. 为什么第一级不是 LLM

第一级跑在 **100% 的流量**上。它的成本、延迟和故障行为因此决定了整个系统的上限：不管它是什么，系统的接入速度不可能快过它，成本不可能低于它，可用性不可能高于它。

所以第一级是：一个关键词词典、一张 source 优先级表、一个哈希 embedding、和一个十项线性模型。它**不擅长细腻的判断，也不需要擅长**。它唯一的工作是：对「明显无聊的东西」判断正确，并且**知道自己什么时候没把握**。凡是它拿不准的，都升级给拿得准的东西。

线性模型刻意做成「拟合出来的逻辑回归」的形状（`ScorerWeights`），所以把直觉换成训练数据是**改十个数字**，不是重写代码。

**`uncertainty` 值得单独说。** 它不是一个「要最大化的置信度」，而是**花钱的依据**。高不确定性意味着廉价层**无法**回答，而这些恰恰是期望回报最高的调用。一个只对「高重要性」升级的系统，会把预算花在确认自己已经知道的事情上。

## 2. 触发器是一个控制问题，不是一个过滤器

```
utility = α·importance + β·novelty + γ·uncertainty + δ·risk − λ·cost
当 utility > θ(预算, 负载, 时效) 时调用
```

阈值是一个**函数**，不是常量 —— 这就是全部的想法。四个策略组合：

| 策略 | θ 依赖于 | 为什么 |
|---|---|---|
| fixed | 什么都不依赖 | 用来衡量其他策略的基线 |
| budget-aware | 当天剩余额度 | 一天里最后的 token 花在当天最值得的事件上 |
| load-aware | 队列深度（二次） | 空闲时宽松，饱和时果断 |
| deadline-aware | 预估等待 vs 时效窗口 | 拒绝那些「答案到达时已经死了」的工作 |

组合规则：**最大阈值生效，显式否决（veto）终局。**

第二条是先成为 bug 才成为规则的。第一版把「某个子策略说不」当成否决，结果整个复合策略塌缩成「碰巧最严格的那个子策略」，静默拒绝了 **48% 的所有 cluster**。现在子策略必须显式打 `veto` 标记（只有 deadline 策略会打），普通的「低于阈值」只贡献它的阈值参与取最大。有一个以这个故障命名的回归测试。

**时效感知是让这个系统成为「决策系统」而不是「队列」的那个策略。** 一条在事故已经恢复四分钟后才产出的摘要不是「部分有价值」，而是**毫无价值**，而且它烧掉的 token 是从还活着的事情那里抢来的。重试同理：一次落在 deadline 之后的重试不是第二次机会，是第二次浪费。

### 两个逃生舱

阈值是统计性的，事故不是。两个机制完全在 utility 计算之外：

**硬安全规则**绕过所有阈值 —— P0 优先级、risk ≥ 0.95、显式 `force_enrich`。前沿扫描证明它在工作：θ=0.95（几乎什么都不准入）时，LLM 调用数仍然停在一个非零下限上，那些就是绕过。

**审计采样**对约 1% 的**被拒绝** cluster 做 enrich，然后**把结果扔掉**。它们永远不进用户 timeline（有测试强制这一点 —— 如果审计输出泄漏进 feed，那这个度量就在度量它自己）。它唯一的目的是从数据估计漏检率，因为**一个悄悄退化的第一级，看起来和一个正常工作的第一级一模一样**。没有它，「我们不会漏掉重要事件」只是一句断言。

## 3. 合并去重，与「模糊地带」

四条「CPU 超过 94%」是**一个事实**。把它们送给模型四次，买到的是同一句话的四份副本。

分组只用廉价信号：同实体、时间接近、embedding 相似。Embedder 会按数量级把数字分桶（`94%` 和 `96%` 都变成 `<num1>`），否则每条遥测都显得「新颖」，合并永远不会触发。

有意思的是中间地带。三个区间：

- 相似度 ≥ 0.80 —— 确信是同一件事，静默合并
- 0.58 – 0.80 —— **合并，但打上 `needs_boundary_check`**
- < 0.58 —— 确信是不同的事，另开一个 cluster

中间地带是整个系统里**最值得花一次 LLM 调用**的地方：一个廉价层已经**证明**自己回答不了的问题（「这些是同一个事故，还是第二个？」）。这些 cluster 在触发器处享受阈值折扣。

### 每个实体保持多个 open cluster

按实体做 key 是对的；每个实体只保持**一个** open cluster 是错的。一个繁忙的 Slack 频道是**一个实体**，但同时承载好几个不相关的对话 —— 单 cluster 设计下，每条新事件都与当前 cluster 不相似，把它以 `topic_changed` 关掉，然后自己开一个，结果**什么都没合并**。Feed 里塞满了近乎重复的单行条目：一页里有五条「sharing a good article on distributed tracing」。

改成对该实体所有 open cluster 取最佳匹配后，在标准轨迹上条目数从 4,718 降到 1,712，R@50 从 89.5% 升到 97.4%。

### 先发布，后分组

上面的修复立刻弄坏了另一件事，而这个「弄坏」比修复本身更有意思。

原本被话题切换提前关掉的 cluster，现在会活满整个窗口 —— 而因为 cluster **只有关闭时才进入 feed**，p95 的「到达 feed 时间」从 18 秒涨到 45 秒。把窗口调窄能把延迟换回来，但同时把分组质量也还回去了。

真正的问题是：`window_seconds` 同时控制**两件互相对立的事** —— 事件分组得多好，和读者要等多久才能看到东西。

现在两者解耦了。`drain_touched()` 在 cluster **打开或增长**时给出一个临时快照，pipeline 就地写入/刷新这个 cluster 的**同一行**。事件在被接入的那一刻就可见，窗口回归为纯粹的分组参数。实测「到达 feed 时间」p50/p95/p99 **全部为 0.00 秒**，同时保留宽窗口和它的分组质量。

一个值得记录的细节：第一版只在**打开**时发布，p95 几乎没动 —— 因为加入已有 cluster 的事件仍然在等关闭。**覆盖「增长」才是真正的修复。**

## 4. 排序，以及它曾经搞错的两件事

排序是系统里最弱的部分。这两个缺陷在聚合指标上完全看不出来，但把前 40 行连同分数打印出来的那一刻就一目了然。

**用户相关性在随新颖度衰减。** `@alice can you review this?` 在第 4 名得 0.400，在第 34 名得 0.251 —— 意图完全相同，分数天差地别。`user_relevance` 会喂进 `importance`，但 novelty 也会，所以第五条措辞相似的 @ 提及看起来就不如第一条重要。**被直接点名是范畴性的**，不会因为措辞变旧就变得不相关。现在它在 `importance` 之外单独参与排序，并且权重更高。

**实体记忆从未参与排序。** 「deployment #813 completed」在词汇上很无聊，关键词打分器不可能知道更多 —— 但**同一句话如果说的是一个当前处于劣化状态的服务**，它就是整个 feed 里最有意思的一行。这个状态一直被追踪着，却只用于构造 prompt。现在它贡献一个加成，而且是**在读取时**施加的，因为「服务已劣化」这个判断通常在那条看起来平平无奇的事件已经写入之后才落地。

两个都有帮助，但都没有填平差距：K=20 时仍然落后全量 LLM（84.2% vs 94.7%）。novelty 在 `importance` 里承担了过多工作，**真正的修复大概是训练一个分类器，而不是继续手调权重**。

## 5. 有界、且公平的调度

每分钟 10,000 事件进来，对上每分钟约 100 事件的 LLM 容量。把剩下的 9,900 条排进队列，会把一个吞吐问题变成一个**无界内存**问题**加上**一个无界延迟问题。

分级有界，每级有不同的溢出策略：

| 级别 | 溢出行为 |
|---|---|
| P0 关键事故 | 预留通道；永不因负载被丢弃 |
| P1 直接用户动作 | 排队；满了就回落到廉价路径 |
| P2 普通项目事件 | 在填满之前先触发更激进的合并 |
| P3 遥测 | 最先被丢，而且安静地丢 |

调度是 **8:4:2:1 的赤字轮询，不是严格优先级**。严格优先级是直觉的选择，而且是错的：持续的 P0 流会**永远**饿死它下面的一切。有一个测试在严格优先级下会失败。

一个值得直说的观察，因为故障注入结果证明了它：**开启负载感知准入后，有界队列几乎从不溢出。** 在实测 45.6 倍负载（3.3 → 151.5 事件/秒）下峰值队列深度是 **0** —— 合并吃掉了 15,872 条事件，utility 阈值拒绝了其余的，负载感知项**根本没被激活**，溢出策略从未运行。

这是好行为，但是坏测试。所以有一个**单独的场景**专门剥掉负载感知、饿死容量，只为了真正跑一遍卸载路径，确认顺序成立（P3 卸载 89 条，P2 回落到廉价路径，P0 和 P1 从不被丢）。

## 6. 实体记忆约束 prompt 成本

一个只是列表的 feed，会让模型每次都重读历史来回答「这条是新的吗」。取而代之，每个实体带一份小而有界的记录：当前状态、近期事件、上次结论、严重度。

模型收到的是**当前 cluster + 该实体的记忆**，而不是 timeline。所以每次调用的 token 成本**不随 feed 的年龄增长**，同时模型仍然获得连续性 —— 记忆把之前调用的结论带了过来。

存储是 LRU 有界的：**无界的记忆就是无界的 prompt 预算和无界的堆**。

## 7. 层级与 supersede

```
raw event → micro → cluster → episode → hourly → daily
```

绝不用一个巨型 prompt。每一层总结下一层，所以日报是在**已经压缩过的文本**上的几次调用，而且每个节点都保留 `source_event_ids`，所以摘要里的任何一行都能展开回原始事实。

Episode 在其实体持续产出材料期间保持**开放**。第一版只汇总「还没见过的」摘要，结果把一个事故切成「每次 rollup 一个 episode」的碎片 —— **比不做汇总更糟**。现在每次都在整个窗口上重建 episode 并 supersede 上一版，故事就地生长。签名检查保证没有变化的 episode 不会被重新叙述，所以安静的一次 tick 成本为零。

廉价路径的事件如果落在一个**已有 open episode** 的实体上，会产出一条 micro 摘要以便被吸收 —— 这就是「deployment #813 completed」（词汇无聊、因果核心）最终出现在「回滚 deployment #813」那个事故 episode **内部**的机制。规则刻意收得很窄：给每一条廉价 cluster 都产出 micro 摘要，会把整个洪流塞进汇总候选集，把 episode 变成噪音的摘要。

而当系统**判断错了** —— 12:05「疑似数据库问题」，12:25「根因确认是 DNS」—— 旧摘要**不会被覆盖**。它被标记为 `SUPERSEDED`、链接到替代者、并保留。修正版**继承**原版的 source events，因为一个修正后的根因仍然必须解释那些导致错误结论的证据。「系统在 12:05 相信什么、为什么」始终可以回答。

矛盾检测刻意保守（共享证据 + 严重度相差 ≥2 级，或显式修正链接）：**漏掉一次 supersede 会留下一条陈旧摘要，这很糟；误判一次 supersede 会毁掉一条正确的，这更糟。**

## 8. 模拟时间，以及第一次为什么做错了

实验台需要在几秒内重放 15 分钟的流量，同时用有意义的单位报告延迟。

**第一次尝试 —— `ScaledClock`：** 真实时间除以一个缩放因子。它撑不过真实轨迹的检验。每次 `asyncio.sleep` 都会因调度开销多睡大约一毫秒，在 50 倍缩放下那一毫秒就是 **50 毫秒模拟时间**。跨越几千个事件后，模拟时钟远远跑到轨迹前面，事件开始在「自己的时效 deadline 之后」到达，**48% 的 cluster 被判为过期**。度量被污染成了看起来像策略结果的样子。

**第二次尝试 —— `VirtualClock`：** 离散事件模拟。**只有在没有任何任务可运行时，时间才前进。** `sleep()` 把调用者挂在一个按唤醒时间排序的堆上；驱动器排空就绪队列，当所有任务都挂起时，把时钟直接跳到最早的唤醒时刻。模拟时长因此是**精确的**，运行速度由 CPU 决定，也没有缩放因子需要调。

它对整个代码库施加了一条约束：**被测系统里任何地方都不能直接调用非零时长的 `asyncio.sleep`。** 这逼出了一个真实改进 —— 调度器的 `dequeue` 原本用超时轮询，那让 worker 永远处于可运行状态，「所有任务都挂起」永远无法成立。现在它等待一个 event。**这在真实时间下也是更好的设计。**

## 9. 学习第一级

第 4 节结尾的结论是「真正的修复大概是训练一个分类器」。`pulsefeed/learning/` 就是它，已建成并测量。**尚未在真实流量或 GPU 上训练过。**

### 标签问题先于模型问题

显而易见的方案是免费标签：LLM 已经标注了每一个被准入的 cluster，severity ≥ ERROR 就是正例。持续、无限、不需要标注员。

它同时也是一个**反馈环**。**标签只存在于当前 scorer 选择准入的事件上。** 只在这些标签上训练，学生学会的是「在学生已经选中的区域复现老师」—— 当前 scorer 系统性漏掉的东西**永远漏掉**，永远不进入训练集，而所有离线指标看起来都非常出色。

审计采样是解药。它是**被拒绝区域的无偏抽样** —— 恰恰是原本不可见的那部分。按倾向性倒数加权（1/0.01 = 100，带上限）后，两者的并集成为对整个流的无偏估计。

效果在采集摘要里直接可见：原始正例率 1.12%，IPS 校正后 **0.34%** —— 因为被准入的 cluster 100% 被 enrich，而被拒绝的只按 30% 采样。

### 结果，包括拟合输掉的地方

| 标签源 | ECE（手调 → 学习） | recall@1%（手调 → 学习） |
|---|---|---|
| ground truth，5.2k / 62 正例 | 0.047 → **0.009** | 0.72 → 0.56 |
| ground truth，41k / 254 正例 | 0.046 → **0.007** | 0.89 → 0.88 |
| LLM teacher + audit，1.6k | 0.057 → **0.017** | 0.14 → **0.29** |

- **校准始终改善 5–7 倍。** 排序指标看不到这一点，而它比排序指标更重要：预算、负载、时效三个阈值策略**都把分数当概率读**。一个排序完美但系统性过度自信的模型，会在 AUC 看起来正常的同时静默破坏这三者。
- **数据量小时，手调先验在排序上赢。** 62 个正例投不过一个精心选择的先验；到 254 个正例时差距归零。这是支持「上生产持续收标签」的论据，不是反对学习的论据。
- **在 teacher 标签上（也就是生产形态），拟合赢，recall@1% 翻倍。**
- **学到的系数独立地印证了手工诊断**：第 4 节手工得出「`user_relevance` 权重不足」，拟合给出 3.3–3.8，而手调值是 1.5。

### 两个建模错误，都被抓住而不是被发布

**不要给已经在 [0,1] 的特征做 z-score。** 这个花了一整轮调试。九个特征全都已经被 clamp 到 [0,1]；`risk` 对多数事件为 0，训练集标准差约 0.06，除下去有效范围变成约 17。拟合出的 logit **饱和**，几百个事件并列在 p = 1.0，排序的头部（触发器唯一会读的部分）变成**随机的**。recall@1% 从 0.48 掉到 0.11，而 ROC-AUC 几乎没动 —— 这正是「AUC 不是运营指标」的原因。

**统计量不能修改数据。** 第一版原地标准化样本，**同时**模型在推理时又标准化一次，双重变换。一个「比较两条本该一致的路径」的单元测试抓到了它。

### 诊断器找出特征集本身的两个缺陷

有了可供检查的拟合才看得见：

- `novelty` 和 `duplication` 相关系数**正好 −1.0** —— 一个的定义就是另一个的 `1 − x`。拟合会把一个效应劈成两个系数，两个都不再可单独解释。
- `recency` 是**常量**：事件在接入时打分，所以年龄永远约等于 0。手调权重给它 0.5，**一直什么都没做**。

两个都记录了，都没删 —— 那会改 `FEATURE_NAMES`，同时作废手调权重和所有已拟合模型，值得一次**有计划的迁移**。

### 老师的目标不是用户的目标

在 `LLM_TEACHER` 标签下，`user_relevance` 系数塌到约 0 —— 因为老师按**严重度**打标签，而「@alice 能帮我 review 一下吗」的严重度是 `info`。它对 Alice 很重要，对一个严重度分类器不重要。

**蒸馏会继承老师被问的问题。**「什么算重要」要在 prompt 里决定，不是在拟合里决定。要么让老师同时回答相关性和严重度，要么让用户相关性作为一条手工规则留在学习模型之外。目前是后者。

## 10. 什么会让我改变想法

- 如果一条真实轨迹显示，廉价 scorer 在「重要性不体现在词汇上」的事件上召回崩溃，那第一级需要的是训练出来的分类器，不是更多关键词。（第 9 节建好了那个分类器；在合成数据上它还没有在排序上赢得自己的位置，只在校准上赢了。）
- 如果审计采样在默认阈值下显示出实质性的漏检率，那默认阈值就是错的、应该调整 —— 这正是采样存在的意义。
- 如果 sentence encoder 在 `recall_at_budget` 上赢不过哈希 embedding，那硬件路线的第 3、4 步应该**砍掉而不是继续** —— 那意味着廉价特征承载了几乎全部信号，而诚实的结论是**这个问题不需要 GPU**。
